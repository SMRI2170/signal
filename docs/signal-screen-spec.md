# SIGNAL Screen Specification

`experience-design.md` の体験原則を、実装・レビュー・Betaテストに使える画面仕様へ落とす。基準は幅360pxの片手操作であり、Desktopはこの情報階層を広げるだけとする。

## 共通フレーム

```
┌──────────────────────── 360px ────────────────────────┐
│ SIGNAL                                      ← BACK     │  44px
│                                                        │
│ [ English label ]       sticker safe zone              │
│ 日本語の主見出し                                           │
│ 意味を補う一文                                             │
│                                                        │
│ 白い主カード                                               │
│                                                        │
│ 主CTA                                                     │
│ 副操作／安心情報                                           │
└────────────────────────────────────────────────────────┘
```

- 左右余白は18px。読み取り本文は最大360px、主カードは画面幅を超えない。
- 上部ナビゲーションは常に44px以上のタップ領域を持つ。
- 1画面に強いCTAは一つだけ。戻る、削除、履歴はテキストリンクまたは二次ボタン。
- ステッカーの安全領域は見出しの右上またはカード外周。本文、フォーム、エラー、CTAには重ねない。
- 下部の主CTAは、キーボード表示中も入力中Ticketを隠さない。固定表示は使わず、自然なスクロールで到達させる。

## 共有コンポーネント

| Component | 役割 | 視覚 | 状態 |
| --- | --- | --- | --- |
| `SceneHint` | 思い出し方を助ける。保存・採点しない | 小さな色付きピル、選択時のみ黒枠 | idle / selected |
| `FactTicket` | 1件の観測事実 | 白い紙片、番号、破線、黒枠 | empty / writing / valid / needs-rewrite |
| `ValidationMirror` | 解釈を責めずに事実へ戻す | Ticket直下の淡色紙片 | observable / interpretation / unclear |
| `SignalReceipt` | 現在地と根拠を読む | 白い分析カード、巨大な数値 | first / up / down / unchanged |
| `EvidenceChip` | 数字の根拠を短く残す | 1行のFact、番号付き | supports / unknown |
| `ThreadNode` | 時点とFactsを結ぶ | 線上の丸＋Ticket | current / past |
| `PrivacyMark` | 私的な記録であることを伝える | 小さな鍵付きラベル | static |

これらは見た目の部品ではなく、同じ意味を毎回同じ形で伝えるUX部品である。

## 01. First Fact — 思い出す入口

### ユーザーの目的

「何を書けばいいか」を迷わず、今頭にある出来事を安全に言語化する。

### 画面

```
WHAT HAPPENED?                                  [ ♥ ]
最近あったこと、
そのまま教えて。
気持ちではなく、相手の発言・行動・回数だけ。

思い出すヒント（任意）
[ 会ったあと ] [ LINEのあと ] [ 次の予定 ]

┌ FACT 01 ─────────── WRITE WHAT HAPPENED ┐
│ 例：相手から来週空いているか聞かれた          │
│                                             │
│ 解釈ではなく、見たこと・聞いたことだけ。 0/300 │
└─────────────────────────────────────────────┘

┌ FACT 02 ────────────────────────────────────┐
│                                               │
└─────────────────────────────────────────────┘

┌ FACT 03 ────────────────────────────────────┐
│                                               │
└─────────────────────────────────────────────┘

+ ADD FACT

[ 3つそろったらSIGNALを見る → ]
```

### 挙動

- `SceneHint` はプレースホルダーだけを切り替える。結果やDBに保存しない。
- 入力開始時、Ticketの枠だけPurpleへ変化する。装飾は増やさない。
- `ADD FACT` は最大10件まで。削除は4件目から表示する。
- 3件未満ではCTAを無効にし、理由は `あと2つでSIGNALを見られます` のように残数で伝える。
- 「最低3件入力してください」だけで終わらせない。

### コピーの判断

- `彼`、`脈あり` は入力面では使わない。観測対象は常に `相手`。
- `正しく書いて`、`間違い` は使わない。`事実として書き換えてみよう` を使う。

## 02. Validation — 事実へ戻る鏡

### ユーザーの目的

否定されたと感じず、分析できる表現へ自分で書き換える。

```
┌ FACT 02 ────────────────────────────────────┐
│ 「最近、なんとなく冷たい」                   │
└─────────────────────────────────────────────┘
┌ MAKE IT CLEARER ─────────────────────────────┐
│ 気持ちの解釈が入っています。                  │
│ 返信がなかった日数や、最後のやり取りを        │
│ そのまま書いてみよう。                         │
│ 例：今週は相手から返信がなかった              │
│ [ 例をコピー ]                                 │
└─────────────────────────────────────────────┘
```

- `observable` はLimeの細いスタンプ `FACT OK`。大きな成功演出をしない。
- `interpretation` と `unclear` はPinkの背景ではなくWhite + Purpleの左罫線。エラー感より可読性を優先する。
- 書き換え例はcopyできるが、ユーザーが自分で確認して入力する。AIが事実を発明しない約束を守る。

## 03. Result — SIGNAL RECEIPT

### ユーザーの目的

数字を過大解釈せず、今見えていることと、まだ判断できないことを理解する。

```
FIRST ANALYSIS                                  [ ✦ ]
┌ SIGNAL RECEIPT ──────────────────────────────┐
│ SIGNAL LEVEL                       FIRST      │
│ 73 / 100                                      │
│                                                │
│ この記録で見えていること                       │
│ [01] 相手から次の予定を聞かれた                │
│ [02] 帰宅後に相手からLINEが来た                │
│                                                │
│ まだ分からないこと                             │
│ 判断材料は3件。次の出来事で変化を見よう。      │
│                                                │
│ 会いたいサイン      81                         │
│ 相手からの積極性    68                         │
│ 判断材料            57                         │
└─────────────────────────────────────────────┘
これは確率ではなく、入力した事実から見えるSIGNALです。

[ この記録を残す → ]
次の出来事と、今日のSIGNALを比べられます。
```

### 必須ルール

- 数字を最も大きくする。ただし `GOOD / BAD` のラベルで感情を誘導しない。
- Evidenceは最大3件、`まだ分からないこと` は最大2件。長文Reasoningを表示しない。
- 初回は `FIRST SIGNAL`。再分析では `前回 61 → 今回 73 / ↑ +12` を同じ位置に出す。
- マイナス差分はPinkではなく、黒文字＋下向き矢印。Pinkは変化や現在地の色であり、失敗の色にしない。

## 04. Save — 私的な記録にする

### ユーザーの目的

何が保存されるかを理解し、本名を出さずに後から見返せるようにする。

```
SAVE YOUR THREAD                                [ 🔒 ]
この記録に名前をつけよう。
本名じゃなくて大丈夫。

[ Aさん                                      ]
候補: [ アプリの人 ] [ 先週会った人 ]

┌ PRIVATE BY DEFAULT ──────────────────────────┐
│ 記録はあなた以外には表示されません。          │
│ いつでも名前の変更・削除ができます。          │
└─────────────────────────────────────────────┘

[ Magic Linkを送る → ]
次の出来事と、今日のSIGNALを比べられます。
```

- 相手名は匿名ラベルとして扱う。プレースホルダーに本名例を使わない。
- Magic Link成功後は、作成したSIGNAL BOARDへ直接移動する。`分析へ戻る` は二次操作。
- 保存時に再分析される理由と、数字がわずかに変わる可能性を一文で明示する。

## 05. Home — LAST THREAD

### ユーザーの目的

前回の状態を一瞬で思い出し、新しいFactを追加する。

```
SIGNAL DESK                                    + ADD
今日の恋、どう動いた？

┌ LAST THREAD ─────────────────────────────────┐
│ Aさん                            10/02       │
│ SIGNAL LEVEL                                  │
│ 73 / 100                         ↑ +12       │
│ 最後のFact: 相手から次の予定を聞かれた        │
│ [ 何かあった？ → ]                            │
└─────────────────────────────────────────────┘

YOUR OTHER THREADS
┌ アプリの人         42 / 100       → ┐
└────────────────────────────────────────┘
```

- 最終更新Relationshipを一つだけ大きくする。複数カードを同じ強さで並べない。
- `何かあった？` は新しいRelationship作成ではなく、そのThreadへ1件追加するCTA。
- 0件時は3つの説明を置かず、Fact入力CTAを一つだけ置く。

## 06. Re-analysis — 新しいFactを糸に足す

### ユーザーの目的

一つの新しい出来事が、今までの記録と比べてどう見えるか知る。

```
FACT 06                                        ← BOARD
新しい出来事、追加しよう。
Aさんとの間で、実際に起きたことだけ。

┌ FACT 06 ─────────────────────────────────────┐
│ 例：相手から来週空いているか聞かれた          │
└─────────────────────────────────────────────┘

[ Factを追加して更新 → ]

UPDATE COMPLETE
前回 61  ───────────────→  今回 73
             +12
今回のFact: 相手から次の予定を聞かれた
[ SIGNAL BOARDを見る → ]
```

- 更新結果は最初に「今回追加したFact」と前後のScoreを並べる。
- スコアだけをカウントアップさせない。TicketがThreadの末尾へ収まる160msの変化で、記録が積み上がったことを示す。
- 更新失敗時は入力を消さず、再試行できる。通信エラーでもTicketの内容は保持する。

## 07. History — THREAD MAP

### ユーザーの目的

スコアの上下を見て終わらず、どの時点で何が積み重なっていたかを確かめる。

```
SIGNAL THREAD MAP                               ← BOARD
Aさんの変化。

  10/05   ● 73  +12 ───── FACT 06
               └ 相手から次の予定を聞かれた
  10/01   ○ 61  +04 ───── FACT 05
  09/28   ○ 57  FIRST ─── FACT 01–04

       9/28 ───── 10/01 ───── 10/05
```

- SVGの線は補助であり、テキストの時点リストが主情報。
- 現在点だけPinkの丸、過去点はCyan。上昇／下降で画面全体の色を変えない。
- 各Nodeは開閉でき、そこまでの直近Factを最大3件読むことができる。
- 1件だけなら線を描かず、`次のFactで変化がつながります` と表現する。

## 動きとフィードバック

| 瞬間 | 表現 | 上限 | 目的 |
| --- | --- | --- | --- |
| Ticketへ入力 | 枠色のみ変化 | 120ms | 現在地を示す |
| Validation通過 | `FACT OK`スタンプ | 160ms | 事実として使えることを示す |
| 実通信の待機 | 状態文とキャンセル操作を表示。進捗値を作らない | 完了まで | 待機と再試行の方法を伝える |
| 分析成功 | FACT TICKETがScannerへ入り、SIGNAL RECEIPTが現れる | 最大480ms | 読み込み完了を記憶に残す |
| Ticket保存 | Thread末尾へ収まる | 160ms | 記録の蓄積を感じさせる |
| Reduced Motion時のResult表示 | TicketとReceiptをopacityだけで切り替える | 180ms | 動きを抑えて結果を示す |

ループ、点滅、パララックス、疑似的なカウントダウンを使わない。Result revealの進捗は描画レイヤーで更新し、ベンチマーク時には再コンポーズ回数とフレーム時間を記録する。

## 実装とデザインの完了条件

- 360px幅で、本文・Ticket・CTAに横スクロールがない。
- 初回分析、Validation、保存、再分析、履歴の全画面で `SIGNAL THREAD`、`Fact`、`Score` の意味が一貫する。
- 他画面と同じ色が、別の意味を持たない。
- 文字・数値だけで意味が伝わり、ステッカーを無効にしても操作できる。
- 新規の画像、Webフォント、アイコンライブラリ、Chartライブラリ、Canvas、WebGLは使わない。
- 5〜10人のBetaテストで、ユーザーが補助なしに初回分析90秒、再分析30秒を完走できる。
