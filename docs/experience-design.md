# SIGNAL Experience Design

## 目的

SIGNALを、恋愛の正解や相手の感情を断定するAIではなく、気になる相手との間で起きた出来事を静かに整理し、時間とともに変化を読める私的な記録体験として設計する。

この文書は機能一覧ではない。画面、言葉、視覚、遷移、空状態、失敗時を同じ体験として判断するための基準である。

## 体験の約束

1. **急かさない** — 不安を煽る通知、連続記録、締切、好意の断定を使わない。
2. **解釈を増やさない** — ユーザーが入力するのは観測した事実だけ。判断の根拠も短く事実へ戻す。
3. **変化を読める** — 現在の数字より、前回から何が変わったかを主役にする。
4. **自分の記録として安心できる** — 相手の本名は不要。公開は既定で行わず、削除できる。
5. **かわいさは操作を助ける** — ステッカーは記録の節目を祝う用途に限定し、入力・根拠・エラーを隠さない。

## 仮説ペルソナ

> 24歳。マッチングアプリで知り合った相手と2回会った。デート後、帰宅してLINEを見返している。相手の気持ちを断定してほしいのではなく、起きたことを忘れずに整理したい。ただし、重い日記アプリや恋愛相談の長文は開きたくない。

これはBeta開始前の仮説であり、性別・性的指向をUIや認可条件に使わない。5〜10人の利用観察で見直す。

## 主要ジョブ

| 状況 | ユーザーの心の声 | SIGNALがすること | してはいけないこと |
| --- | --- | --- | --- |
| デートやLINEの後 | 「あれ、どう受け取ればいい？」 | 事実を3つだけ書けるように助ける | 好意がある／ないを断定する |
| 初回結果 | 「この数字は何を意味する？」 | 根拠と判断材料の量を短く見せる | 73を恋愛成功確率に見せる |
| 次の出来事 | 「前より何か変わった？」 | 1件のFactで前回との差分を見せる | 全入力を最初からやり直させる |
| 数日〜数週間後 | 「私の思い込みじゃなかった？」 | 時系列とFactを一緒に見返せる | ストリークや不安を煽る通知を出す |
| 保存・共有 | 「これは人に見られない？」 | 匿名ラベル、削除、非公開既定を明示する | 本名・Fact本文を共有へ含める |

## 体験フロー

### 1. 初回分析 — 90秒以内

1. LPのCTAを押す。
2. `WHAT HAPPENED?` で、3枚のFact Ticketを読む。
3. 各Ticketには空欄の代わりに、思い出すためのヒントを出す。
   - 最後に会ったとき、相手が言った／したこと
   - 直近の連絡で、回数や時刻を含めて書けること
   - 次の予定について、決まった事実
4. 入力後にFact Validationを行い、解釈があれば理由と書き換え例をそのFactの直下に示す。
5. 結果では、SIGNAL LEVEL、判断材料の量、主な根拠をこの順に示す。

### 2. 保存 — 20秒以内

結果を先に見せ、保存時だけMagic Linkを使う。保存理由は「今日の数字を残す」ではなく「次の出来事と比べられるようにする」。

- 匿名ラベルを選ぶ／入力する。例：`Aさん`、`アプリの人`、`先週会った人`
- 本名を入力する必要はないことを表示する。
- 認証完了後は、必ず作成したRelationshipのSIGNAL BOARDへ遷移する。
- 再分析で値がわずかに変わる可能性を、保存前に一行で伝える。

### 3. 再訪 — 30秒以内

Homeでは、最も最近更新したRelationshipを最初に表示する。主CTAは常に「新しいFactを追加」。

1. `何かあった？` を押す。
2. 1枚の新しいFact Ticketに入力する。
3. Validationが通る。
4. `前回 61 → 今回 73` と、今回のFact／短い根拠を表示する。
5. `SIGNAL TAPE` で変化の文脈を見返せる。

## 画面設計

### Landing

- 役割：サービスの仕組みを誤解なく理解させ、最初のFact入力へ進ませる。
- 最初の画面で伝えることは3つだけ。
  1. 起きたことだけを記録する
  2. 数字は確率ではなくSIGNALスコア
  3. 新しい出来事があるたび変化を追える
- ステッカーは世界観を作る。説明文の上には置かない。

### Fact Input — FACT TICKET

- 役割：思い出しやすく、解釈を混ぜず、入力疲れを起こさない。
- 初回は3枚、再分析は1枚。最大10枚。
- Ticketには番号、短いヒント、文字数、削除操作を置く。
- `分析する` は、必要件数と文字数を満たしたときのみ有効にする。
- エラーは色だけで区別せず、`書き換えが必要です` と理由を明記する。
- 書き換え例はコピーしやすくするが、自動挿入はしない。

### Result — SIGNAL RECEIPT

- 役割：不安を煽らず、結果と次の行動を理解させる。
- 情報階層：
  1. `SIGNAL LEVEL 73 / 100`
  2. `FIRST SIGNAL` または `↑ +11 前回比`
  3. 主なEvidence Label（最大3件）
  4. 判断材料の量
  5. 3つの補助指標
  6. 「確率ではない」説明
- 低い／停滞した値は赤い警告として扱わない。`今回のFactでは大きな変化は見えません` のように中立に表現する。
- 保存CTAの近くに、今後の比較価値を一文で置く。

### Home — SIGNAL DESK

- 役割：一覧ではなく、次に記録するRelationshipをすぐ選べる場所。
- カードには匿名ラベル、現在値、前回比、最後の更新日を表示する。
- 最も最近更新したカードを一番大きくする。
- 0件時は説明で埋めず、最初のFact追加CTAを一つだけ置く。

### Relationship Detail — SIGNAL BOARD

- 役割：今の状況と、次にやることをひと目で理解させる。
- 最上部は現在値と前回比。補助指標はその下。
- その下に今回の変化を生んだFact、次に追加するCTA、履歴への導線を置く。
- 更新・名称変更・削除は、視覚的には主役にしないが、必ず発見可能にする。

### History — SIGNAL TAPE

- 役割：数字の上下と、その時点までの事実を同じ文脈で確認する。
- グラフはRomantic Interestだけを主線にする。
- 各点は日付、スコア、前回比、Fact数をテキストでも読める。
- 点を開くと、その時点までの直近Factを最大3件表示する。
- 1件しかない場合も壊れず、「次のFactで変化が見える」と表現する。

## 視覚システム

### 情報と装飾の比率

- 70%：白い分析カード、読みやすい日本語、数値、Fact本文
- 20%：Pink / Purple / Cyan / Lime / Yellow の背景面、ラベル、スコア
- 10%：ステッカー、ハーフトーン、ホログラム、斜めのアクセント

### ステッカーの役割

- 画面ごとに原則1〜3個。
- 使う場面：開始、保存完了、変化、履歴の節目。
- 使わない場面：エラー、プライバシー説明、Fact本文、入力中の主要操作。
- 白いカットライン、黒い輪郭、hard shadow、既存6色のホログラムを共通構造にする。

### タイポグラフィと言葉

- 英語：ブランド、ステッカー、短いラベル。例：`SIGNAL LEVEL`、`FACT TICKET`
- 日本語：意味、説明、エラー、次の行動。
- 数字：常にtabular-numsで、`73` を最も大きくする。
- 禁止語：`脈あり確定`、`彼はあなたが好き`、`今すぐ行動`。

### モーション

- 意味のある変化だけに120〜180msのtransform / opacityを使う。
- Ticket追加、保存完了、スコア差分に限定する。
- 常時浮遊、パララックス、点滅、カウントダウンは使わない。
- `prefers-reduced-motion` では静止状態を完全に利用可能にする。

## モバイル基準

- 基準幅：360px、390px、430px。
- 最小タップ領域：44px。
- キーボード表示中も、入力中Ticketと送信CTAを隠さない。
- 1画面に主CTAは1つ。副操作はテキストリンクにする。
- 200% Zoom、キーボード操作、スクリーンリーダーで同じ情報順を維持する。

## Betaで検証するタスク

5〜10人に、誘導せず次のタスクをしてもらう。

1. 最近の出来事を3つ記録する。
2. 解釈を含むFactを、自分で書き換える。
3. 結果が「確率ではない」と理解できるか説明してもらう。
4. 結果を保存し、後からどこへ行けば追加できるか探してもらう。
5. 1件追加後、何が変わったか説明してもらう。
6. 自分のデータを消せる場所を探してもらう。

成功の目安は、補助なしで初回分析を90秒以内、再分析を30秒以内に完了でき、結果の意味を誤って「相手が自分を好きな確率」と説明しないこと。

## 実装前のゲート

新しい機能を追加する前に、以下を満たす。

- 保存前に匿名ラベルを設定できる。
- 保存後に作成したSIGNAL BOARDへ直接遷移する。
- 初回・再分析の両方でFact Validationの理由と書き換え例を表示する。
- ResultにEvidence Labelと次のFact追加導線がある。
- Relationshipの名称変更・削除・データ削除説明がある。
- 上記Betaタスクを実ブラウザの360px / 390px / 430pxで確認する。

## 体験の固有性 — SIGNAL THREAD

SIGNAL固有の体験は、AIが恋愛を「診断」することではない。Factを足すたびに、自分だけの関係の流れが一本の線として育つことにある。この体験を **SIGNAL THREAD（事実の糸）** と呼ぶ。

- 1つのFactは、タイムラインに留まる小さなTicketである。
- 1回の分析は、Factを裁くイベントではなく、今までのTicketを同じ基準で読み直すイベントである。
- Scoreは糸の現在地を示す印で、相手の感情や未来を予言するものではない。
- Historyはチャートではなく、いつ何が起き、どのFactが重なったかを読み返す私的な地図である。

この比喩により、初回は「3枚のTicketを並べる」、再訪時は「1枚を糸に足す」、履歴では「糸をたどる」という、他のAI恋愛サービスにはない一貫した身体感覚を作る。

## ユーザーの感情から決める画面状態

### A. 書き始める前 — 期待と戸惑い

**気持ち**：何を書けばよいか分からない。間違ったことを書いて評価されたくない。

**UI**：空欄を3つ並べるだけではなく、保存されない `SCENE HINT` を置く。

- `会ったあと`
- `LINEのあと`
- `次の予定が動いたとき`

これはカテゴリ入力でもプロフィール情報でもない。選択するとTicketのプレースホルダーだけが変わる。例：`相手が言ったこと／したことをそのまま書く`。選ばなくても分析できる。

**成功条件**：ユーザーが「何を書けばよいか」を他人に尋ねず、10秒以内に最初のTicketへ入力を始められる。

### B. Validation — 恥ずかしさと不安

**気持ち**：「書き方が悪い」と否定されたくない。

**UI**：エラーではなく `MAKE IT CLEARER` として表示する。

- `「冷たい気がする」には気持ちの解釈が入っています`
- `相手の返信がなかった日数など、見たことに置き換えてみよう`
- 書き換え例は淡い紙片として出し、押すとコピーできる。自動入力はしない。

**禁止**：赤い警告面、バツ印だけ、AIが勝手に文章を書き換えて保存すること。

### C. 分析中 — 待ちと疑念

**気持ち**：AIが何をしているのか分からず、結果を待って不安が増える。

**UI**：派手なAI演出や無限スピナーではなく、3段階の静かな進行を示す。

1. `Factを確認中`
2. `同じ基準で整理中`
3. `SIGNALをまとめています`

各段階はTicketのスタンプが1つ付く短いCSSアニメーションにする。6秒を超えたら、入力を保持していることと再試行できることを明記する。

### D. 結果を見る — 安堵と次の不安

**気持ち**：数字をすぐ意味づけたい。一方、悪い結果で傷つきたくない。

**UI**：最初に数字を見せるが、数字だけでは終わらせない。

```
SIGNAL LEVEL
73 / 100

この記録で見えていること
・相手から次の予定を聞かれた
・帰宅後に相手からLINEが来た

まだ分からないこと
・判断材料は3件。変化を見るには次のFactが必要
```

正負ではなく、`見えていること` と `まだ分からないこと` を必ず対にする。低い値や前回比マイナスも、警告色や「BAD SIGNAL」とは表現しない。

### E. 保存する — 警戒と納得

**気持ち**：メール登録に価値があるか、相手の情報が安全か知りたい。

**UI**：CTAは `この記録を残す`。その直下に価値とプライバシーを1文ずつ表示する。

- `次の出来事と、今日のSIGNALを比べられます`
- `本名は不要。記録はあなた以外には表示されません`

Magic Linkの前に匿名ラベルを設定する。推奨候補は `Aさん`、`アプリの人`、`先週会った人`。本名はプレースホルダーにも表示しない。

### F. 再訪する — 一瞬で前回を思い出す

**気持ち**：前に何を記録したか忘れている。長い履歴は読みたくない。

**UI**：Homeの主役はカード一覧ではなく、最後に触ったRelationshipの `LAST THREAD`。

- 前回のScoreと更新日
- 最後のFactを最大1件
- `何かあった？` の1操作CTA

他のRelationshipはその下に小さく束ねる。ユーザーが一番多く使う画面は、次のFactを足す入口である。

## 画面間のつながり

ページを切り替えるたびに別のプロダクトへ移動したように感じさせない。共通の要素は、位置と意味を固定する。

| 要素 | 固定する意味 | 画面での見せ方 |
| --- | --- | --- |
| SIGNAL THREAD | Factの蓄積 | 入力ではTicketの積み重ね、履歴では一本の線 |
| Score Mark | 現在地 | `73 / 100` の数字と前回比。確率記号は使わない |
| Evidence Chip | 数字の根拠 | 事実の短文。結果、詳細、履歴で同じ文言を使う |
| Privacy Mark | 私的な記録 | 保存前・共有前・削除付近で同じ鍵付きラベル |
| Add Fact | 再訪の行動 | 常に `何かあった？` または `Factを追加` と表現 |

## Trend translation: 採用するもの、採用しないもの

最新の表現をそのまま輸入せず、SIGNALの用途へ変換する。

| 現在の潮流 | SIGNALでの採用 | 採用しない理由 |
| --- | --- | --- |
| Collage / scrapbook | 白いカットラインのSVG、Ticket、わずかな斜め配置 | 写真や多数の装飾でFactの可読性を下げない |
| Bold type | Scoreと日本語コピーを大きく、数字を主役にする | 装飾英語が説明を置き換えない |
| Retrofuturism / holo | Purple・Cyan・Pink・Lime・Yellowだけの小さなホログラム | WebGL、動画、重い3Dモデルは使わない |
| Functional motion | Ticket追加、Validation通過、Score差分だけを120〜180msでつなぐ | 常時浮遊、パララックス、待機を引き延ばす演出は使わない |
| Calm personalization | 状況に合わせて変わる入力ヒント。プロフィール収集はしない | 性別、恋愛対象、本名、感情の推測を保存しない |

## 視覚の密度ルール

### 80 / 20 の原則

- 80%は、白い紙面、黒い本文、明確な数値、観測可能なFact。
- 20%だけを、ステッカー、色面、ホログラム、ハーフトーンに使う。

これにより、最初の一瞬はスクリーンショットしたくなるY2Kの強さを持ち、読み返すときは疲れない。

### 色の意味

| 色 | 役割 | 使ってはいけない役割 |
| --- | --- | --- |
| Pink | 現在地、更新、感情の熱量 | 下落やエラーの警告 |
| Purple | SIGNALの計算・分析領域 | 本文の長文背景 |
| Cyan | 履歴、確認、補助情報 | 低コントラストの本文 |
| Lime | 次のFact追加、準備完了 | 好意があるという判定 |
| Yellow | Ticket、ヒント、短い祝福 | 常時表示の主背景 |
| Black / White | 読む、区切る、守る | 装飾だけのための大量使用 |

## 軽量性をデザイン品質として扱う

軽量であることは、読み込みの速さだけではなく、不安なときに操作がすぐ返るという体験品質でもある。

- LCPはテキストとCSS背景だけで成立させる。Hero画像を必要としない。
- ステッカーは既存のインラインSVGだけ。新規のPNG / WebPを本番へ追加しない。
- 新しいWebフォント、アイコンライブラリ、Chartライブラリ、Canvas、WebGLを導入しない。
- 1画面の背景テクスチャはCSS擬似要素を1枚まで。アニメーション対象はtransform / opacityのみ。
- 画像や非同期要素には必ず領域を予約し、入力中にCTAが移動しないようにする。
- `prefers-reduced-motion`、キーボード、200% Zoomを通常の体験と同じ設計対象にする。

## 体験の検証方法

独自性はデザインレビューだけでは保証できない。Betaで次の問いに答えられたときに初めて担保される。

1. 初見の人は、SIGNALを恋愛相談AIではなく「事実の記録」と説明できるか。
2. 3つのFactを書き始めるまで迷わないか。
3. `73 / 100` を好意の確率だと誤解しないか。
4. 再分析後、何がScoreの変化につながったかを自分の言葉で説明できるか。
5. 「何かあったらまた開く」と感じる自然な入口があるか。
6. 記録を残すことに対して、プライバシー上の不安を感じないか。

各問いで失敗した場合、機能追加より先にコピー、階層、画面遷移、または入力ヒントを見直す。
