# SIGNAL Experience Design

## 目的

SIGNALを、恋愛の正解や相手の感情を断定するAIではなく、気になる相手との間で起きた出来事を静かに整理し、時間とともに変化を読める私的な記録体験として設計する。

この文書は機能一覧ではない。画面、言葉、視覚、遷移、空状態、失敗時を同じ体験として判断するための基準である。

## 体験の約束

1. **急かさない** — 不安を煽る通知、連続記録、締切、好意の断定を使わない。
2. **解釈を増やさない** — ユーザーが入力するのは観測した事実だけ。判断の根拠も短く事実へ戻す。
3. **変化を読める** — 現在の数字より、前回から何が変わったかを主役にする。
4. **自分の記録として安心できる** — 相手の本名は不要。公開は既定で行わず、削除できる。
5. **かわいさは操作を助ける** — ステッカーは記録の節目を祝う用途に限定し、入力・根拠・エラーを隠さない。

## 仮説ペルソナ

> 24歳。マッチングアプリで知り合った相手と2回会った。デート後、帰宅してLINEを見返している。相手の気持ちを断定してほしいのではなく、起きたことを忘れずに整理したい。ただし、重い日記アプリや恋愛相談の長文は開きたくない。

これはBeta開始前の仮説であり、性別・性的指向をUIや認可条件に使わない。5〜10人の利用観察で見直す。

## 主要ジョブ

| 状況 | ユーザーの心の声 | SIGNALがすること | してはいけないこと |
| --- | --- | --- | --- |
| デートやLINEの後 | 「あれ、どう受け取ればいい？」 | 事実を3つだけ書けるように助ける | 好意がある／ないを断定する |
| 初回結果 | 「この数字は何を意味する？」 | 根拠と判断材料の量を短く見せる | 73を恋愛成功確率に見せる |
| 次の出来事 | 「前より何か変わった？」 | 1件のFactで前回との差分を見せる | 全入力を最初からやり直させる |
| 数日〜数週間後 | 「私の思い込みじゃなかった？」 | 時系列とFactを一緒に見返せる | ストリークや不安を煽る通知を出す |
| 保存・共有 | 「これは人に見られない？」 | 匿名ラベル、削除、非公開既定を明示する | 本名・Fact本文を共有へ含める |

## 体験フロー

### 1. 初回分析 — 90秒以内

1. LPのCTAを押す。
2. `WHAT HAPPENED?` で、3枚のFact Ticketを読む。
3. 各Ticketには空欄の代わりに、思い出すためのヒントを出す。
   - 最後に会ったとき、相手が言った／したこと
   - 直近の連絡で、回数や時刻を含めて書けること
   - 次の予定について、決まった事実
4. 入力後にFact Validationを行い、解釈があれば理由と書き換え例をそのFactの直下に示す。
5. 結果では、SIGNAL LEVEL、判断材料の量、主な根拠をこの順に示す。

### 2. 保存 — 20秒以内

結果を先に見せ、保存時だけMagic Linkを使う。保存理由は「今日の数字を残す」ではなく「次の出来事と比べられるようにする」。

- 匿名ラベルを選ぶ／入力する。例：`Aさん`、`アプリの人`、`先週会った人`
- 本名を入力する必要はないことを表示する。
- 認証完了後は、必ず作成したRelationshipのSIGNAL BOARDへ遷移する。
- 再分析で値がわずかに変わる可能性を、保存前に一行で伝える。

### 3. 再訪 — 30秒以内

Homeでは、最も最近更新したRelationshipを最初に表示する。主CTAは常に「新しいFactを追加」。

1. `何かあった？` を押す。
2. 1枚の新しいFact Ticketに入力する。
3. Validationが通る。
4. `前回 61 → 今回 73` と、今回のFact／短い根拠を表示する。
5. `SIGNAL TAPE` で変化の文脈を見返せる。

## 画面設計

### Landing

- 役割：サービスの仕組みを誤解なく理解させ、最初のFact入力へ進ませる。
- 最初の画面で伝えることは3つだけ。
  1. 起きたことだけを記録する
  2. 数字は確率ではなくSIGNALスコア
  3. 新しい出来事があるたび変化を追える
- ステッカーは世界観を作る。説明文の上には置かない。

### Fact Input — FACT TICKET

- 役割：思い出しやすく、解釈を混ぜず、入力疲れを起こさない。
- 初回は3枚、再分析は1枚。最大10枚。
- Ticketには番号、短いヒント、文字数、削除操作を置く。
- `分析する` は、必要件数と文字数を満たしたときのみ有効にする。
- エラーは色だけで区別せず、`書き換えが必要です` と理由を明記する。
- 書き換え例はコピーしやすくするが、自動挿入はしない。

### Result — SIGNAL RECEIPT

- 役割：不安を煽らず、結果と次の行動を理解させる。
- 情報階層：
  1. `SIGNAL LEVEL 73 / 100`
  2. `FIRST SIGNAL` または `↑ +11 前回比`
  3. 主なEvidence Label（最大3件）
  4. 判断材料の量
  5. 3つの補助指標
  6. 「確率ではない」説明
- 低い／停滞した値は赤い警告として扱わない。`今回のFactでは大きな変化は見えません` のように中立に表現する。
- 保存CTAの近くに、今後の比較価値を一文で置く。

### Home — SIGNAL DESK

- 役割：一覧ではなく、次に記録するRelationshipをすぐ選べる場所。
- カードには匿名ラベル、現在値、前回比、最後の更新日を表示する。
- 最も最近更新したカードを一番大きくする。
- 0件時は説明で埋めず、最初のFact追加CTAを一つだけ置く。

### Relationship Detail — SIGNAL BOARD

- 役割：今の状況と、次にやることをひと目で理解させる。
- 最上部は現在値と前回比。補助指標はその下。
- その下に今回の変化を生んだFact、次に追加するCTA、履歴への導線を置く。
- 更新・名称変更・削除は、視覚的には主役にしないが、必ず発見可能にする。

### History — SIGNAL TAPE

- 役割：数字の上下と、その時点までの事実を同じ文脈で確認する。
- グラフはRomantic Interestだけを主線にする。
- 各点は日付、スコア、前回比、Fact数をテキストでも読める。
- 点を開くと、その時点までの直近Factを最大3件表示する。
- 1件しかない場合も壊れず、「次のFactで変化が見える」と表現する。

## 視覚システム

### 情報と装飾の比率

- 70%：白い分析カード、読みやすい日本語、数値、Fact本文
- 20%：Pink / Purple / Cyan / Lime / Yellow の背景面、ラベル、スコア
- 10%：ステッカー、ハーフトーン、ホログラム、斜めのアクセント

### ステッカーの役割

- 画面ごとに原則1〜3個。
- 使う場面：開始、保存完了、変化、履歴の節目。
- 使わない場面：エラー、プライバシー説明、Fact本文、入力中の主要操作。
- 白いカットライン、黒い輪郭、hard shadow、既存6色のホログラムを共通構造にする。

### タイポグラフィと言葉

- 英語：ブランド、ステッカー、短いラベル。例：`SIGNAL LEVEL`、`FACT TICKET`
- 日本語：意味、説明、エラー、次の行動。
- 数字：常にtabular-numsで、`73` を最も大きくする。
- 禁止語：`脈あり確定`、`彼はあなたが好き`、`今すぐ行動`。

### モーション

- 意味のある変化だけに120〜180msのtransform / opacityを使う。
- Ticket追加、保存完了、スコア差分に限定する。
- 常時浮遊、パララックス、点滅、カウントダウンは使わない。
- `prefers-reduced-motion` では静止状態を完全に利用可能にする。

## モバイル基準

- 基準幅：360px、390px、430px。
- 最小タップ領域：44px。
- キーボード表示中も、入力中Ticketと送信CTAを隠さない。
- 1画面に主CTAは1つ。副操作はテキストリンクにする。
- 200% Zoom、キーボード操作、スクリーンリーダーで同じ情報順を維持する。

## Betaで検証するタスク

5〜10人に、誘導せず次のタスクをしてもらう。

1. 最近の出来事を3つ記録する。
2. 解釈を含むFactを、自分で書き換える。
3. 結果が「確率ではない」と理解できるか説明してもらう。
4. 結果を保存し、後からどこへ行けば追加できるか探してもらう。
5. 1件追加後、何が変わったか説明してもらう。
6. 自分のデータを消せる場所を探してもらう。

成功の目安は、補助なしで初回分析を90秒以内、再分析を30秒以内に完了でき、結果の意味を誤って「相手が自分を好きな確率」と説明しないこと。

## 実装前のゲート

新しい機能を追加する前に、以下を満たす。

- 保存前に匿名ラベルを設定できる。
- 保存後に作成したSIGNAL BOARDへ直接遷移する。
- 初回・再分析の両方でFact Validationの理由と書き換え例を表示する。
- ResultにEvidence Labelと次のFact追加導線がある。
- Relationshipの名称変更・削除・データ削除説明がある。
- 上記Betaタスクを実ブラウザの360px / 390px / 430pxで確認する。
